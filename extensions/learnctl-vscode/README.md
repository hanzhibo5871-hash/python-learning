# Python 学习工作台

在 VS Code 中阅读 learnctl 课程、改写并运行教学示例、完成本地作业、查看验收反馈，并直接向 AI 助教提问。v0.3 使用现有课程与后端验证器，适用于此仓库的 Python 学习路径。

## 安装与开始

1. 在 VS Code 扩展面板右上角 `…` 选择 **从 VSIX 安装**，选择 `learnctl-python-learning-0.3.0.vsix`。
2. 打开课程根目录，例如 `D:\codex\MY-工作台`，该目录应包含 `data/curriculum.json`、`learnctl` 和项目 `.venv`。
3. 点击左侧书本图标 **Python 学习**。侧栏提供当前课程小节与完整课程目录，课程总览展示 29 课、4 个阶段及完成状态。
4. 点击小节，先阅读 **知识讲解** 中的讲解、代码和预期输出。首次打开以及从 v0.2 升级时先进入知识页；升级保留已有聊天和草稿。
5. 在可独立运行的 Python 教学代码旁点击 **在编辑器尝试**，打开独立示例文件。修改代码后点击 **保存并运行示例**，在终端观察结果，再回到讲解理解差异。
6. 进入 **本节作业** 页，阅读要求并点击 **准备并打开作业**，在正常代码编辑器中编写。
7. 点击 **保存并检查**，或在作业编辑器按 `Ctrl+Alt+Enter`（macOS 为 `Cmd+Alt+Enter`）。该动作保存 `learner_workspace` 内已打开的作业及辅助模块，再验收磁盘内容；不顺带保存教学示例的修改。
8. 阅读课程面板及 **Python 学习检查** 输出面板中的检查项、程序输出和错误，修改后再次检查。
9. 全部必修小节通过后，点击面板的 **完成整课**，或侧栏的 **填写运行证据，登记本课完成**，填写实际命令和结果。后端核验通过后才进入下一课。

侧栏顶部可返回今日课程、选择其他课程或刷新进度。面板支持上一节、下一节、代码复制和知识目录导航。反复检查或刷新会保留学习面板的分栏位置；移动面板后也会保留新位置。切换小节再回来会保留本次会话的检查结果；代码修改后会标记结果已过期。

D01–D06 保留网页入门练习；D07 起正式作业在本地编辑器完成。AI 助教为可选功能，无 Key 也能阅读课程并完成本地验收。

## 教学示例

**在编辑器尝试** 只准备并打开文件，不自动运行。示例放在 `learner_workspace/examples/<课程>/<小节>/`，与正式作业分开；再次准备不会覆盖自己的修改，关闭并重新打开后文件仍保留。

**保存并运行示例** 先保存当前示例，再用课程 Python 解释器运行真实文件，工作目录是该小节的独立示例目录。VS Code 终端支持 `input()` 输入，可以按 `Ctrl+C` 停止程序。运行时留意终端中的输出和错误；任务启动本身不表示程序已运行成功。

如果使用 VS Code 的普通 Python 运行按钮，请先按 `Ctrl+S` 保存，并确认当前文件就是要运行的 `.py` 文件。跟练教学代码时使用面板的独立示例入口，示例不写入正式作业。

只有课程明确标记为可独立运行的 Python 代码提供这些操作。命令、网页代码和依赖上下文的文件片段需要按讲解放到指定位置。教学示例运行不创建正式作业、不登记小节通过，也不计为课程完成。

## Python 环境

默认明确使用课程项目中的 `.venv/Scripts/python.exe`（Windows）或 `.venv/bin/python`。如需其他环境，在 VS Code 设置中填写 `learnctl.pythonPath`，支持绝对路径及相对课程根目录的路径。解释器不存在时直接显示启动错误，不搜索系统 Python。

插件不依赖 Microsoft Python 扩展；安装它可以获得 Python 补全和调试功能。

## 验收与进度

- 所有准备、验收和完成动作调用现有 `python -m learnctl`，插件不直接写入进度。
- 已有作业文件不会被准备动作覆盖；检查不会从网页草稿或起始模板取代实际文件。
- 验收通过只登记本节完成。整课完成需要全部必修通过、实际证据和原有后端门禁。
- 连续项目的多个小节可能共用文件。先在侧栏选中正在学习的小节，再点该节的检查按钮；快捷键在不能确定小节时会显示选择器。
- 作业检查调用本地验证器。AI 问答单独执行，不会登记小节或整课完成，也不启动网页服务。
- 同一时刻执行一个课程操作；打开的工作区需要被 VS Code 信任。

## AI 助教

打开当前小节的 **AI 答疑** 页签，点击 **配置 DeepSeek** 输入自己的 API Key，再用 **测试连接** 检查配置。插件固定使用 `deepseek-flash`，明确关闭 thinking，用于快速答疑。真实连接和问答会访问 DeepSeek 官方 API，需要用户提供有效 Key；课程学习和本地检查无需 Key。

可输入问题、点击常用问题，或按 `Ctrl+Enter` 发送。需要解释一段代码时，在当前作业、辅助模块或本节教学示例中选中代码后使用 **Python 学习：让 AI 解释选中代码**，也可在提问前勾选 **带上选中代码**。AI 等待回答期间可以继续阅读和切换小节；**取消请求** 会中止本地请求进程，取消后的回答不会写入历史。

发送给 DeepSeek 的内容包括当前课程、小节知识和作业要求、问题及最近 6 条本节历史。勾选 **带上已保存作业** 时，额外附带当前作业文件与本节明确提供的辅助模块；勾选 **带上选中代码** 时，附带选中片段，可包含未保存修改。尚未过期的本地验收摘要也会附带。插件不会遍历整个课程工作区来收集代码。

问题、回答、输入草稿、阅读页签和上下文选项保存在 VS Code 的本地工作区状态中，按课程根目录、任务和小节隔离；重新打开仍可继续。每节最多保留 20 条对话消息。**清空对话** 只清空当前小节的历史与草稿，独立保留课程进度和作业文件。

Key 使用 VS Code `SecretStorage` 保存。插件不把它写入课程、进度、对话、网页内容或进程参数；调用后端时仅通过 UTF-8 JSON stdin 传入本地 Python 进程。**移除 Key** 删除插件保存的凭据。若 Python 进程已有 `DEEPSEEK_API_KEY`，状态会显示环境变量来源，应从对应进程环境中移除该配置。

AI 或课程操作失败时展示后端返回的错误文本，供你据此修改配置或作业。AI 解释不替代本地验证器的完成判断。

## 开发与验证

源码为 CommonJS JavaScript，无运行时 npm 依赖。打开本扩展目录按 F5 启动开发宿主，然后在新窗口打开课程根目录。

```powershell
npm test
npm run check
npx @vscode/vsce package --allow-missing-repository
```

`test/vscode-smoke.js` 必须在专用临时课程工作区运行。启动器应创建 `vscode-offline-smoke.json` 标记并复制测试课程及进度，不能指向真实学习目录。测试通过真实 VS Code `ProcessExecution` 运行教学 Python 文件；AI 仅在隔离副本中指向本地 HTTP 服务，使用虚构 Key。完整验收通过两个 `--extensionDevelopmentPath` 分别加载生产扩展与临时测试驱动，不使用内存状态的 `--extensionTestsPath` 宿主；驱动运行测试后正常关闭窗口，仅在隔离状态中模拟 v0.2 的阅读位置，再次启动验证升级、聊天草稿和示例文件的保留。通过后生成 `vscode-smoke-result.json`。离线通过不代表已验证真实 DeepSeek 连接。

本地 VSIX 安装不需要发布到扩展市场。
